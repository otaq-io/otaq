# T10. `otaq helper drop`: the agent in charge drops a piece (N16)

**Depends on:** T4, T5 (merged). **Runs in parallel with:** T9, T11, T12.

Read `ideas/noyan-intake/DECISIONS.md` first (N8, N9, N16). Read `ideas/noyan-intake/tasks/T4-findings.md` and the
"With a Plan: work as the agent in charge" section of `plugin/skills/work-ticket/SKILL.md`.

## What to change

1. **A new command, `otaq helper drop <n> --stdin`** (the reason on stdin; refused when empty). Follow how
   `helper back` and `helper merge` are built end to end: CLI (`crates/otaq-cli/src/cli.rs` and its handler), the
   request and protocol (`crates/otaq-core/src/protocol.rs`; regenerate `protocol.snapshot.json` as the snapshot test
   says), the policy (`crates/otaq-core/src/policy.rs`: the agent in charge of that ticket only; the user, helpers,
   Noyan and other tickets' agents are refused, as for `helper merge`), and `crates/otaq-core/src/helpers/`.
2. **What it does:**
   - stops the piece's helper session, if it runs;
   - removes the helper's worktree and branch, the way `helper merge` cleans up after a merge;
   - marks the piece **dropped** (a new helper status next to working / handed back / sent back / merged; add a
     migration only if the status is stored in a column with a constraint, with the next free number);
   - records a History event on the ticket with the reason ("40.3 dropped · <reason>"), shown in the History view
     (`crates/otaq-view/src/view_models/history.rs`);
   - replies with one line the agent sees, for example
     `Dropped 40.3 (Wishlist page): its helper stopped and its branch is gone. Take it out of the Plan with
     \`otaq update --plan-stdin\`.`
   - Refusals: an unknown piece, a merged piece ("40.1 is merged already"), an already dropped one.
3. **Dropped pieces afterwards:** `helper start <n>` refuses a dropped number (like a merged one); `helper list` and
   `prime` show it as dropped; wherever the app shows piece rows (card, sheet: search `otaq-view` and the UI for the
   helper status), dropped reads as dropped, not as working or missing. If a UI type is generated by `ts-rs`, keep
   `ui/src/generated/` fresh (`cargo test -p otaq-desktop generated_types_are_fresh`).
4. **`plugin/skills/work-ticket/SKILL.md`:** where the skill says to tell a removed piece's helper to stop and never
   merge it ("The Plan changed" step and the T5 warning "Don't remove a piece whose helper still works"), use
   `otaq helper drop <n> --stdin` instead, then take the piece out of the Plan. Keep the rest of T5's text.
5. **README.md:** if it lists the helper commands, add `helper drop` in the same style.
6. **Tests:** an integration test in `crates/otaq-core/tests/suite/` (follow `plan_mid_build.rs`): drop a working
   piece → session stopped, worktree and branch gone, status dropped, History event, `helper start` refused; refusals
   for the user, a helper, another ticket's agent, a merged piece, an empty reason. Add the CLI's command check if
   the CLI suite has one (`every_command_and_flag_a_skill_names_exists` must keep passing). Update the work-ticket
   needles in `crates/otaq-core/tests/suite/plugin.rs` (`work_ticket_runs_helpers_as_the_agent_in_charge`).
